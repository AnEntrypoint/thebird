gm-tooling: rs-plugkit's DECIDE->COMPLETE submodules-clean gate check had a false-positive bug: git rev-parse HEAD run with cwd set to an UNINITIALIZED submodule directory (no .git of its own) silently walks up to the parent repo and returns its HEAD instead of erroring, spuriously flagging drift for consumer repos whose submodules were never `git submodule update --init`'d. Fixed 2026-08-07 in AnEntrypoint/rs-plugkit commit 0bdf455 (check pkfs::exists(path/.git) before trusting rev-parse; skip uninitialized submodules) plus gm's own submodule pointer bump commit 90111ff6. Also fixed fsm.rs's hardcoded gm-specific submodule names in the gate error message. Daemon wasm auto-update has its own ~600s poll cycle before a source fix takes effect live even after CI-green push -- rebooting the watcher does not force immediate pickup, only waiting does.
