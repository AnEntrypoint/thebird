# thebird

A Node CLI and library whose every operation dispatches through gm tooling.

- Runtime surface: `bin/thebird.js`, `bin/thebird-relay.js`, `src/index.js`,
  `src/api.js`, `src/gm.js`, `src/gm-client.js`, `src/gm-remote.js`,
  `src/relay.js`, `src/commands.js`, `src/runner.js`, `src/cli.js`,
  `web/terminal.html`, `web/terminal.js`, `web/gm-worker.js`,
  `web/gm-worker-client.js`, `web/shims/*.js`, `src/shim-map.js`,
  `scripts/browser-driver.mjs`, `scripts/vendor-bashkit.mjs`, `scripts/vendor-pyodide.mjs`, `web/bash-shell.js`,
  `web/shims/bashkit-host.js`, `web/vendor/acorn.mjs`, `web/git-in-page.js`,
  `web/vendor/isomorphic-git.mjs`, `web/commit-gate.js`, `web/sqlite-in-page.js`,
  `web/vendor/sqljs/sql-wasm-browser.js`, `web/python-in-page.js`,
  `web/curl-in-page.js`, `web/shell-lookup.js`, `web/ansi.js`.
- Browser-safe: `src/api.js`, `src/commands.js`, `src/runner.js`,
  `src/gm-client.js`, `src/gm-remote.js`, `web/terminal.js`. They import
  nothing from Node and run in a browser. Node-only: `src/gm.js`,
  `src/relay.js`, `src/index.js`, `src/cli.js`, `bin/`.
- The browser terminal keeps its command history in the page's localStorage under
  `thebird.history`. It stores only the submitted command lines, capped at 500, and
  no output, cwd or other state.
- The browser terminal shows plain text by default: ANSI escape sequences are stripped
  (`web/ansi.js`), so output copies cleanly. `?ansi=color` renders colour and style as
  spans; the page text is the same in both modes.
- `web/shims/*.js` are browser-only and import only each other. They replace
  the `node:` modules gm uses: fs (OPFS-backed, sync), fs/promises, path,
  crypto (sha1 and sha256), and stubs for child_process, os, util and friends.
  Add a shim here before adding a `node:` import to gm-facing code.
- `web/vendor/pyodide/` is generated by `scripts/vendor-pyodide.mjs`, gitignored,
  and pinned by SHA-256. Its licence notice is `web/vendor/PYODIDE-NOTICE.md`.
- `web/vendor/bashkit/` is generated by `scripts/vendor-bashkit.mjs` and is
  gitignored. Run the script after a fresh clone; the witness runs it when the
  files are missing. It needs network and checks the wasm SHA-256.
- The default browser terminal runs gm in `web/gm-worker.js` over OPFS. It
  does not need the relay, except for loading the static files. `?engine=relay`
  sends gm calls to the relay on the host instead.
- The browser terminal (relay mode) runs in a page served by the relay. Its gm calls go
  to the relay over same-origin HTTP (`GET /meta`, `POST /call`, and `POST /cancel`
  to abort a `/call` by its id), so shell,
  git, jobs and filesystem run on the host. The relay binds 127.0.0.1 by
  default, runs commands as the user, and answers only JSON POSTs, which a
  cross-origin page cannot send without a CORS preflight the relay does not
  answer. Keep it that way.
- gm is the only execution engine. Do not reimplement filesystem, search,
  shell, git, job, log, wiki, row or fetch behavior locally.
- In-page `which`, `type` and `command -v` are one answer. `web/shell-lookup.js` defines shell functions for `which`, `command` and `type` at shell start, over bashkit's own `builtin command -v` and `builtin type`, so each name resolves the same way in all three. The five in-page builtins (`git`, `sqlite3`, `python3`, `curl`, `wget`) report as builtins, not as `/usr/bin` paths. `which` prints the name for a builtin, as `command -v` does, and `type -t` says `builtin`. Shell functions are visible to `type` and `compgen -c`, so the prologue's three names appear as functions; `type -a` is not handled.
- `node` is relay-only. No in-page runtime is verified: WebContainers is proprietary, and a JS subset is not Node, so the in-page shell answers `node` with exit 127 and says that compilers and build tools are not available in the sandbox; `?engine=relay` runs the host's `node`.
- `createGmClient()` resolves `--gm-home` / `GM_HOME` / an installed `gm`
  package / `../gm` / `./gm`, then imports gm's `createTools()` verb engine.
- CLI commands and library methods must be thin mappings to gm verbs.
- Unknown gm verbs pass through unchanged, so new gm verbs need no thebird change.
- `job_start` maps to gm's `run_shell` with `background: true` because gm's in-process engine has no separate job-start verb.
- Validation is `npm run witness`, which runs the real CLI paths plus the
  Node-side runner and library checks. There is no test suite.
- Use Conventional Commits.
