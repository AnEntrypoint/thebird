# thebird

A bash terminal that runs in the browser. Node serves the static files and nothing else.

## Runtime surface

- Node only: `bin/thebird-relay.js`, `src/relay.js`.
- Browser (page and worker): `web/terminal.html`, `web/terminal.js`, `web/shell-client.js`, `web/shell-worker.js`, `web/bash-shell.js`, `web/shell-lookup.js`, `web/git-in-page.js`, `web/commit-gate.js`, `web/sqlite-in-page.js`, `web/python-in-page.js`, `web/curl-in-page.js`, `web/quickjs-in-page.js`, `web/ansi.js`, `web/shims/*.js`.
- Vendored: `web/vendor/acorn.mjs`, `web/vendor/isomorphic-git.mjs`, `web/vendor/sqljs/`, and the generated `web/vendor/bashkit/`, `web/vendor/pyodide/` and `web/vendor/quickjs/`.
- Scripts: `scripts/browser-driver.mjs`, `scripts/build-pages.mjs`, `scripts/lint-architecture.mjs`, `scripts/lint-comments.mjs`, `scripts/vendor-bashkit.mjs`, `scripts/vendor-pyodide.mjs`, `scripts/vendor-quickjs.mjs`, `scripts/witness.mjs`, `scripts/witness-quickjs.mjs`.
- QuickJS-ng wasm wrapper: `scripts/quickjs/thebird-eval.c`, built only by `scripts/vendor-quickjs.mjs`.

## Browser and Node split

- Everything under `web/` is browser-only. It imports nothing from Node. `web/shims/` modules import only each other.
- `src/relay.js` and `bin/` are Node-only.
- Add a shim in `web/shims/` before adding a `node:` import to in-page code.
- The relay answers GET and HEAD only, binds `127.0.0.1` by default, and must keep sending `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp`.

## Comments

- Repo-owned code has no comments. `npm run lint:comments` lists each one with its file and line, and exits non-zero when there are any.
- When a change touches a file, remove the comments in that file as part of the change. Prose that cannot become self-explanatory code moves to `AGENTS.md` or `ARCHITECTURE.md`, after checking it is still true.
- Shebang lines in `bin/` are syntax, not comments.
- Vendored bundles keep their upstream comments and are not edited. `lint:comments` reports them as VENDORED and fails a vendored file with comments that has no provenance entry in `scripts/lint-comments.mjs`.

## Vendored and generated files

- `web/vendor/acorn.mjs`, `web/vendor/isomorphic-git.mjs` and `web/vendor/sqljs/` are committed with licence files (`ACORN-LICENSE`, `ISOMORPHIC-GIT-LICENSE`, `SQLJS-LICENSE`). Do not edit them.
- `web/vendor/bashkit/` and `web/vendor/pyodide/` are generated by `scripts/vendor-bashkit.mjs` and `scripts/vendor-pyodide.mjs`, gitignored, and checked against pinned SHA-256 values. Run the scripts after a fresh clone; they need network.
- pip loads micropip from the CDN at run time, pinned to the vendored Pyodide version, and fetches pure wheels from PyPI. Packages in the vendored lock are refused. Do not add wheels to `web/vendor/` without owner approval.

## Browser state

- History is kept in localStorage under `thebird.history`. It stores only the submitted command lines, capped at 500. No output, cwd or other state.
- Output is plain text by default: `web/ansi.js` strips escape sequences. `?ansi=color` renders colour and style as spans, and the page text is the same in both modes.
- `which`, `command -v` and `type` are defined in `web/shell-lookup.js` and must agree for every in-page builtin. The builtins are `git`, `sqlite3`, `python3`, `pip`, `qjs`, `curl` and `wget`.

## Timeout

`COMMAND_TIMEOUT_MS` in `web/bash-shell.js` is 300000 and is passed to bashkit's `Bash` as `timeoutMs`. Do not lower it. bashkit's 30 s default is too short for a cold `pip install`, as recorded in `ARCHITECTURE.md`. Change the value only with a witnessed cold install.

## Cancel

- Ctrl-C ends a `curl`, `wget` or `pip install` waiting on the network. The fetch is aborted, the command exits 130 with `cancelled`, and the page leaves the busy state. `pip install` aborts both the micropip wheel download and each PyPI request, and the next install works after a cancel.
- `git` has no network await in the page: `clone`, `fetch`, `pull` and `push` are refused before any request is made, so there is nothing to abort.
- `python3` has no network await, and its code runs synchronously in the worker. Ctrl-C is not delivered until the script returns: the page stays busy, and the script output still prints. Ending a busy script needs a shared-memory interrupt, which needs cross-origin isolation, and the Pages site does not have it.

## Hosting

- `.github/workflows/pages.yml` builds `_site/` with `scripts/build-pages.mjs` on each push to `main` and deploys it to GitHub Pages. The page needs no cross-origin isolation headers, and the witness runs the built site without them.
- The build job has `contents: read` only. The deploy job alone has `pages: write` and `id-token: write`. The witness checks both blocks.
- The actions in `pages.yml` are pinned to full commit SHAs: actions/checkout `11d5960a326750d5838078e36cf38b85af677262` (v4), actions/setup-node `49933ea5288caeca8642d1e84afbd3f7d6820020` (v4), actions/upload-pages-artifact `56afc609e74202658d3ffba0e8f6dda462b719fa` (v3), actions/deploy-pages `d6db90164ac5ed86f2b6aed7e0febac5b3c0c03e` (v4). Each SHA was resolved with `git ls-remote` and confirmed as a commit by `gh api repos/<repo>/git/ref/tags/<tag>`.
- Pinning matters because the deploy job holds `pages: write` and `id-token: write`, and a moved tag would change the code that runs with them. To upgrade, resolve the new SHA the same way, change the `uses:` line, and update this list.
- Do not add a root-absolute path such as `/web/...` to browser code. The Pages site sits under `/thebird/`, so every URL in `web/` is relative to the file that holds it.

## Commit gate

`web/commit-gate.js` is the in-page gate for `git commit`. It checks the index, staging, syntax (acorn), ASCII, the four docs and their repo paths, and a git object round trip. It is not a semantic review. Keep its checks and its `NOT_COVERED` list in step with the code, and with `ARCHITECTURE.md`.

## QuickJS-ng milestone 1

- `scripts/vendor-quickjs.mjs` builds quickjs-ng v0.18.0 (source archive sha256 `28bcd89aa3683fd2a946537e5ce3f11cc46b5cbf3383c7561aaef3df5ff9f1dd`) into `web/vendor/quickjs/qjs.wasm`, a WASI reactor, with zig 0.17.1 (the official x86_64-linux tarball, installed at `/workspace/tools/zig-x86_64-linux-0.17.1` on this machine). Run it with `ZIG=/path/to/zig npm run vendor:quickjs`. `web/vendor/quickjs/` carries its own `.gitignore` that ignores everything but itself.
- The wasm pin is `63748df2bd9299200c85815da6e4bffc72a26748f14345d5060ebc204e7ebbad`, recorded in `scripts/vendor-quickjs.mjs`. Two clean builds with the script produced identical bytes on this machine. The vendor script and the witness both fail when the artifact does not match the pin.
- The build is reproducible only with fixed paths. The script builds in `$TMPDIR/thebird-quickjs/src` with relative source names, uses the cache `$TMPDIR/thebird-quickjs/zig-cache`, and prefix-maps the repo root and zig's lib dir. The binary still embeds zig's libc source paths, and those and the build paths are specific to this machine. Another zig install or temp directory needs a re-pin.
- `scripts/witness-quickjs.mjs` (`npm run witness:quickjs`) instantiates the wasm with `node:wasi` and runs 10 evaluations: arithmetic, JSON, BigInt, a regex, Unicode case mapping, an uncaught `TypeError`, and a `SyntaxError`. It exits 0 only when the artifact matches the pin and every evaluation matches.
- `scripts/quickjs/thebird-eval.c` exports `thebird_eval(ptr, len)`. It copies the input into a NUL-terminated buffer, evaluates it in global scope, and returns the value or `Uncaught <message>`. QuickJS's lexer reads past the input length, so the copy is required.
- Milestone 1 ran the engine under Node with `node:wasi`. Milestone 2 runs it in the page: `web/shims/wasi-preview1.js` supplies the WASI imports the reactor uses (the rest return ENOSYS), and `web/quickjs-in-page.js` loads `./vendor/quickjs/qjs.wasm` on first use. The `qjs -e <code>` builtin exposes it: console output is returned, and an uncaught exception is an error. The Pages build does not run zig, so the artifact is absent there and `qjs` reports that the engine is not built. The libuv replacement is not started.

## Fresh-tree notes

- A tree from `git archive` has no `.git`. The lints call git, so they cannot run there.
- The architecture lint's live checks need `web/vendor/bashkit/` and `web/vendor/pyodide/` present. The lint does not generate them.
- The `cc242f5` record (the owner commit) is handled as follows. It PASSes when `cc242f5` resolves to a commit object. It is UNVERIFIED (no history) only when the object does not resolve and the tree has one commit. It FAILs when the object does not resolve on a tree with more history.

## Working rules

- Use Conventional Commits.
- Open, flaky: once, a witness run stalled for about 16 minutes after the streamed-output checks, in the terminal block that stores submitted lines. `send` in `scripts/browser-driver.mjs` had no timeout, and `waitFor` checks its deadline only between `evaluate` calls. The stall is not reproduced: the re-run finished with `WITNESS-EXIT 0`. `send` is now bounded at 60 s through `withTimeout`, and the witness checks that a call which never answers aborts.
- `THEBIRD_WITNESS_FIXTURE=desynced-mapping npm run witness` feeds a desynced mapping to the drift check in memory, with gh unavailable. The run must exit 1 with the local FAIL line. Without the variable the run exits 0. No file on disk changes.
- On a slow link the bashkit wasm (7.8 MB) can take minutes to load. The live check passed in 238738 ms with a 1200 s limit, so use a long timeout for live checks on such a network.
- Validation: `npm run check`, `npm run lint:comments`, `npm run lint:architecture`, and `npm run witness`. The witness drives headless Chromium through `scripts/browser-driver.mjs`; set `CHROME_BIN`. There is no test suite.
